# 实时行情注入方案（P5）

- 交付时间：2026-09-12
- 触发问题：用户问「现在的股市行情如何」时，系统只能回答「背景资料未包含实时行情数据」
- 结论：**静态知识库被用来回答动态事实问题**，属能力错配，非检索 bug；已通过「行情类问句注入实时快照」修复

## 一、问题定位（真实日志证据）

```
19:41:46 | INFO  | 流式问答 - 意图: domain=stock_market
19:42:27 | WARN  | _rerank_context | 检索结果全部低于相似度阈值 0.7，回退原始 Top-5
19:42:59 | INFO  | qwen3.7-flash 生成完成
```

知识库收录的是制度性/投教类**静态**资料，与「现在多少点」无共同语义空间 → 重排分必然低于 0.7 → 回退 Top-5 → LLM 只能说「资料里没有」。调阈值、加 few-shot 都治不了，必须补**动态数据源**。

## 二、方案

在**共享上下文构建点** `routers/chat.py::_build_context` 注入行情块。选这一点的原因：老链路 `/chat/`、`/chat/stream`、统一编排 `/chat/ask`、MCP 工具 `finrag.kb_search` 四处全部经过它，一处接入、全部生效。

```
提问 ──► 意图识别 ──► [新增] 行情类问句判定 ──► 取行情快照 ──┐
                                                     │（失败则跳过，行为同升级前）
                                                     ▼
                        知识库混合检索 → 精排 ──► 行情块 + KB块 拼接 ──► LLM
```

### 1. 问句判定（规则，零开销）

`services/market_data.py::is_realtime_query()`

- **强信号**：行情 / 大盘 / 点位 / 涨跌幅 / 涨停 / 跌停 / 收盘价 / 开盘价 / 股指 / 走势 / 涨了 / 跌了 …
- **弱信号**：主体词（股市 / A股 / 沪指 / 上证 / 深证 / 创业板 / 沪深300 / 科创50 / 指数…）**与** 时间状态词（现在 / 今天 / 最新 / 实时 / 多少点 / 涨 / 跌 / 收盘…）同时出现

保守策略：宁可少注入，也不要在制度性问句里塞行情数据（污染上下文）。实测 13/13（6 正例 + 7 负例，含「什么是指数基金」「股票发行注册制改革」等易误触发问句）。

### 2. 取数（多源 + 缓存 + fail-soft）

| 项 | 设计 | 原因 |
|---|---|---|
| 主源 | 腾讯行情 `qt.gtimg.cn`（GBK 文本协议） | 实测 urllib 可直连 |
| 备源 | 东方财富 push2（JSON） | 东财 push2 **会拒绝部分 urllib 客户端**（RemoteDisconnected），单源不可靠 |
| provider | `auto`：依次尝试，谁成功用谁 | 抗单点失效 |
| 超时 | 3s | 行情是增强项，不能拖慢主链路 |
| 缓存 | 进程内 TTL 30s；失败结果短缓存 10s | 休市/连续追问不重复打接口；离线时不再每次白等超时 |
| 失败 | 记 WARNING 日志 → 返回空串 | **绝不抛异常、绝不影响知识库检索** |

覆盖标的：上证指数、深证成指、创业板指、沪深300、科创50（`[market_data] tencent_symbols/eastmoney_symbols` 可配）。

### 3. 上下文块（自带来源与时间说明）

```
【实时行情数据】（数据时间：2026-09-11 16:14:03；来源：腾讯财经公开行情接口）
- 上证指数（000001）：3888.11，跌 46.29，跌幅 1.18%
- 深证成指（399001）：13471.26，跌 146.41，跌幅 1.08%
…
说明：当前为休市日（周末），以上为最近一个交易日的收盘数据。
回答要求：行情/涨跌/点位类问题请优先依据以上实时数据作答，并注明数据时间；
知识库检索到的制度性、投教类内容属于静态资料，请与实时行情区分表述，不得相互混淆。
```

块内自带「交易时段 / 盘前 / 盘后 / 休市日」判定与吐答要求，无需改 LLM prompt 模板。

### 4. 配套必须做的事（否则会答错）

| 项 | 处理 | 不做的后果 |
|---|---|---|
| **缓存旁路** | 行情类问句不读、不写 `finrag:qa:` / `ask:` 缓存 | 24h 缓存会把「某时点的行情」冻住，用户第二天还看到昨天的数 |
| **BM25 早退让路** | 行情类问句跳过 BM25 早退 | FAQ 命中直接返回静态答案，行情注入永远走不到 |
| **零命中兜底** | 知识库无命中但有行情 → 返回行情上下文，而不是「未找到资料」 | 行情类问句本就不该依赖知识库命中 |
| **溯源不写死** | `sources[0]` 的 source / source_url / 数据时间取自**真实生效源** | 曾出现「数据来自腾讯、标注写东财」的不一致 |

`sources[0]` 结构（`type` 供前端与 Agent 区分展示）：

```json
{"question": "实时行情快照（2026-09-11 16:14:03）", "score": 1.0,
 "source": "腾讯财经公开行情接口", "source_url": "https://gu.qq.com/",
 "type": "realtime_market"}
```

## 四、验证证据

**离线复验（`scripts/test_market_data.py`）**

- 问句识别 13/13（6 正例全 True、7 负例全 False）
- 真实取数 5 条指数成功，耗时 0.16~1.17s；缓存命中 0.0000s
- 断网（指向 127.0.0.1:9）→ `fetch → None`、`context → ''`，无异常

**集成复验（`scripts/test_market_integration.py`）**

- 行情块拼在 KB 上下文之前，`sources = [realtime_market, kb...]`
- 零命中也返回行情上下文（不再答「未找到资料」）
- 非行情问句行为与升级前完全一致（无行情块；零命中仍返回空）
- 5 项缓存旁路 / BM25 让路源码级断言全过

**真实 LLM 端到端（8010 端口独立实例，qwen3.7-flash）**

| 提问 | 结果 |
|---|---|
| 现在的股市行情如何 | 引用 5 大指数真实涨跌 + 数据时间 + 休市说明，标注来源「腾讯财经公开行情接口」 |
| 今天上证指数和创业板指涨跌多少 | 3888.11 跌 1.18% / 3322.04 跌 0.49%，均带数据时间 |
| 存款保险最高赔付多少（对照） | 行为不变，50 万元限额，`sources` 无 `realtime_market` |

## 五、边界与后续

- **只覆盖指数级行情**：个股、板块、期货、基金净值未覆盖（可扩 `symbols` 配置，或后续接行情 API）。
- **不构成投资建议**：模型可能顺带给出「关注政策落地」这类表述；若要严格合规，可在 context 块追加「不得给出投资建议」的硬约束。
- **休市日体验已处理**：明确标注「最近一个交易日收盘数据」，不会让用户误以为是实时盘中价。
- **可观测**：`market_data.snapshot_stats()` 提供缓存条目与最近一次取数状态，需要时可挂到 `/health/ready`。
